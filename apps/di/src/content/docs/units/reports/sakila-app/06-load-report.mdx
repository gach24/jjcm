Ya tienes el catálogo de informes cargado en `Sidebar` y compartido con `ReportsContext`. El siguiente salto es **cargar el informe seleccionado** (PDF) desde JasperReports Server y renderizarlo en el área principal (`Main`) como una vista previa.

El último commit del proyecto de referencia hace tres cosas clave:

- Añade **selección de informe** desde `Sidebar`.
- Ejecuta el informe (descarga `blob`) y genera una **URL `blob:`** reutilizable en un `iframe`.
- Introduce **estado de carga y error** específico para la ejecución del informe (`loadingReport`, `errorLoadingReport`), separado de la carga del listado.

### Paso 1 — API: `getReportUrl()` devuelve una URL `blob:`

En `src/api/jasper-report-api.ts` renombra y ajusta la función que ejecuta el informe:

```diff lang="ts" title="src/api/jasper-report-api.ts"

// ... login() u otras funciones ya definidas ...

export const getReportUrl = async (
	reportPath: string,
	format = "pdf",
	params?: Record<string, any>
): Promise<string> => {
   const response = await httpClient.get(`/reports${reportPath}.${format}`, {
     responseType: 'blob',
     params: params
     params,
   });
 
	return URL.createObjectURL(response.data);
};
```

<Aside type="note" title="¿Por qué devolver string?">
  La UI suele querer algo embebible (`iframe src=`) o descargable (`a href=`).
  Una `blob:` URL cubre ambos casos.
</Aside>

### Paso 3 — Hook: selección + ejecución + revocación de blob URLs

Implementa en `src/hooks/useReports.ts`:

- `selectedReport` como driver de ejecución.
- `load()` como acción manual (para “Re-ejecutar”).
- `reportUrl` como `blob:` URL (revocando la anterior para no filtrar memoria).

```diff lang="ts" title="src/hooks/useReports.ts"
 import { useCallback, useEffect, useState } from "react";
-import { getReports } from "../api/jasper-report-api";
+import { getReport, getReports } from "../api/jasper-report-api";

 export const useReports = () => {
 	// ... listado (reports/loadingReports/errorLoadingReports) ...
+
+	const [selectedReport, setSelectedReport] = useState<Report | null>(null);
+
+	const [loadingReport, setLoadingReport] = useState(false);
+	const [errorLoadingReport, setErrorLoadingReport] = useState<string | null>(null);
+	const [reportUrl, setReportUrl] = useState<string | null>(null);
+
+	const load = useCallback(async () => {
+		if (!selectedReport) return;
+
+		setLoadingReport(true);
+		setErrorLoadingReport(null);
+
+		try {
+			const url = await getReport(selectedReport.uri);
+			setReportUrl((prev) => {
+				if (prev) URL.revokeObjectURL(prev);
+				return url;
+			});
+		} catch (e: any) {
+			setErrorLoadingReport(e?.message ?? String(e));
+		} finally {
+			setLoadingReport(false);
+		}
+	}, [selectedReport]);
+
+	useEffect(() => {
+		void load();
+	}, [load]);

 	return {
 		// ... list ...


+    reportUrl,
+    loadingReport,
+    errorLoadingReport,

+    selectedReport,

+    // Functions
+    /** Updates the selected report (will trigger execution via the effect). */
+    setSelectedReport,
+
+    /** Alias for `load()` (re-execute selected report). */
+    reload: load,
 	};
};
```

<Aside type="caution" title="Importante: revocar blob URLs">
  Si no haces `URL.revokeObjectURL(prev)`, cada ejecución deja un blob “vivo” en
  memoria. En sesiones largas, se nota.
</Aside>

## 🧩 Aplicación en el proyecto

- Separas claramente **dos cargas**: `loadingReports` (catálogo) y `loadingReport` (ejecución). Esto evita UI confusa.
- La selección de informe se convierte en un **evento de dominio** (`setSelectedReport`) y el hook decide qué hacer (ejecutar + generar URL).
- La UI deja de “saber HTTP”: `Main` solo necesita `reportUrl` para renderizar.

## Resumen rápido

| Objetivo            | Dónde queda                                   |
| :------------------ | :-------------------------------------------- |
| Seleccionar reporte | `Sidebar` → `setSelectedReport(report)`       |
| Ejecutar reporte    | `useReports.load()` → `getReport(uri)`        |
| Visualizar PDF      | `Main` con `iframe src={reportUrl}`           |
| Evitar leaks        | `URL.revokeObjectURL(prev)` en `setReportUrl` |

## Convención práctica

<Steps>
  1. Nombra flags por “qué se está cargando” (`loadingReports` vs
  `loadingReport`) para que el render sea trivial. 
  2. Si usas `blob:` URLs, **revócalas** al reemplazarlas (y opcionalmente al desmontar). 
  3. Mantén las “acciones” (`load`) en el hook/context y “render” en componentes: menos acoplamiento, más testabilidad.
</Steps>
