## Inicialización del Proyecto

Comenzaremos creando un proyecto base limpio y añadiendo las dependencias necesarias para la comunicación con el servidor de informes.

<Steps>
1.  **Crear el proyecto con Vite:**
    Genera la estructura base seleccionando **React** y **TypeScript**.
    ```bash
    npm create vite@latest reports-client-app -- --template react-ts
    cd reports-client-app
    ```

2.  **Instalar dependencias:**
    Añadiremos `lucide-react` para la iconografía y `axios` para las llamadas al servidor.
    ```bash
    npm install lucide-react axios tailwindcss @tailwindcss/vite
    ```

3.  **Configurar Vite para Tailwind CSS:**
    Añadiremos la configuración de Tailwind CSS a nuestro proyecto.    
    ```diff lang="ts" title="vite.config.ts"
      import { defineConfig } from 'vite';
      import react from '@vitejs/plugin-react'; 
    + import tailwindcss from '@tailwindcss/vite';

      // https://vite.dev/config/
      export default defineConfig({
    -    plugins: [ react()],
    +    plugins: [tailwindcss(), react()],
      });
    ```

    Vacía el contenido de `src/index.css`. Y añade el siguente contenido
    ```css title="src/index.css"
    @import "tailwindcss"; 
    ```	

4.  **Limpieza inicial:**
    Elimina los archivos innecesarios para empezar desde cero con nuestra propia arquitectura.
    - Borra `src/App.css`.

    - Reinicia `src/App.tsx` para que solo contenga un fragmento con un título de prueba.
    ```ts title="src/App.tsx" {4-6}
    function App() {
      return (
        <>
          <h1 className="text-3xl font-bold underline">
            Hello world!
          </h1>
        </>
      )
    }

    export default App;
    ```

5.  **Ejecutar la aplicación:**
    Ejecuta la aplicación para verificar que todo está funcionando correctamente.
    ```bash
    npm run dev
    ```

    Ahora deberías poder ver el título de prueba en la pantalla.

6.  **Hacer un commit de los cambios. (Opcional)** 
    ```bash title="Terminal" "tu-repo-en-github.com"
    git init
    git add .
    git commit -m "Initial app structure"
    git branch -M main
    git remote add origin tu-repo-en-github.com
    git push -u origin main
    ```
</Steps>

## Estructura y Layout Base

Nuestra aplicación seguirá un patrón clásico de **Panel de Control**: una barra lateral para el listado de informes y un área principal para la visualización.

### Preparación del Estilo Global

Añadiremos unas clases base en `src/index.css` para gestionar el layout flexible y el aspecto visual de los contenedores:

```css
#root {
  max-width: 1280px;
  margin: 0 auto;
  padding: 2rem;
  text-align: center;
}

.app-layout {
  display: grid;
  grid-template-columns: 300px 1fr;
  gap: 1.5rem;
  height: calc(100vh - 4rem);
}

.glass {
  background: rgba(255, 255, 255, 0.05);
  backdrop-filter: blur(10px);
  border: 1px solid rgba(255, 255, 255, 0.1);
  border-radius: 12px;
}
```

### Componentes de Estructura

Definiremos dos componentes principales en `src/App.tsx`: `Aside` (lateral) y `Main` (contenido).

```tsx
import { Aside } from './components/Aside';
import { Main } from './components/Main';

function App() {
  return (
    <div className="app-layout">
      <Aside />
      <Main />
    </div>
  );
}

export default App;
```

<Aside type="tip" title="Separación de responsabilidades">
	Aunque al principio parezca tentador poner todo en `App.tsx`, crear los archivos `Aside.tsx` y `Main.tsx` en una carpeta `src/components` facilitará enormemente la gestión del estado y la lógica de los informes más adelante.
</Aside>

## Aplicación en el proyecto

La creación de esta aplicación es el punto de partida para integrar el sistema de informes en una solución de escritorio real. En este paso:

- **Estandarizamos el acceso**: Preparamos la aplicación para autenticarse contra JRS.
- **Definimos el visor**: Reservamos el espacio donde se renderizará el PDF o HTML devuelto por el servidor.
- **Gestionamos la navegación**: El lateral se convertirá en un buscador dinámico de los informes disponibles en el repositorio.

## Convención práctica

<Steps>
1.  Usa siempre nombres de componentes en PascalCase (`Aside.tsx`, `Main.tsx`).
2.  Mantén el estado de la aplicación (el reporte seleccionado) en el componente padre `App.tsx` para que ambos paneles puedan reaccionar a los cambios.

</Steps>
