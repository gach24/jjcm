La integración con JasperReports Server conviene **separarla en dos capas**:

1. **`src/api/jasper-report-api.ts`** — funciones que hablan HTTP (`login`, `getReports`, …) reutilizando el `httpClient` (Axios) del paso anterior.
2. **`src/hooks/useReports.ts`** — hook que **orquesta React**: estado, efecto de montaje y consumo de `getReports`.

Esta sección implementa **`getReports`** y el hook mínimo que lo consume.

### Paso 1 — `getReports` en la capa API

Añade (o completa) en **`src/api/jasper-report-api.ts`** la función que devuelve el listado de unidades de informe: `GET` con `Accept: application/json` y retorno de `data.resourceLookup`.

```ts title="src/api/jasper-report-api.ts"
import httpClient from '../config/jasper-report-client';

// ... login() u otras funciones ya definidas ...

/**
 * Obtiene el listado de informes publicados en JasperReports Server
 * (unidades de informe, recursivo).
 */
export const getReports = async (): Promise<unknown[]> => {
	const { data } = await httpClient.get('/resources?type=reportUnit&recursive=true', {
		headers: {
			Accept: 'application/json',
		},
	});
	return data.resourceLookup ?? [];
};
```

<Aside type="note" title="Ruta del cliente Axios">
	El import `../config/jasper-report-client` debe coincidir con el **nombre real** del fichero donde creaste `axios.create` en [el apartado de proxy y Axios](./03-axios-configuration). Si ahí usaste otro nombre (por ejemplo `jasper-reports-client.ts`), ajusta solo la ruta.
</Aside>


## Paso 2 — Hook `useReports`

Crea **`src/hooks/useReports.ts`** importando `getReports` desde la API. El flujo habitual es: estado inicial vacío, **un efecto sin dependencias** que llama a `getReports` al montar, y `return { reports }`.

```tsx title="src/hooks/useReports.ts"
import { useEffect, useState } from 'react';
import { getReports } from '../api/jasper-report-api';

export const useReports = () => {
	const [reports, setReports] = useState<unknown[]>([]);

	useEffect(() => {
		let cancelled = false;

		getReports()
			.then((data) => {
				if (!cancelled) {
					setReports(data);
				}
			})
			.catch((e) => {
				console.error(e);
			});

		return () => {
			cancelled = true;
		};
	}, []);

	return {
		reports,
	};
};
```

<Aside type="note" title="Estado, tipos y desmontaje">
  cancelled evita un problema típico de async + React:

  El useEffect llama a getReports() (asíncrono).
  La promesa puede resolver después de que el componente ya se desmontó (el usuario salió de la pantalla, cambió de ruta, etc.) o después de que el efecto se limpió porque cambió algo y se volvió a ejecutar.
  Si en el .then haces setReports(data) en ese caso, React te avisará con algo como "Can't perform a state update on an unmounted component" y en general estás actualizando estado de un componente que ya no debería reaccionar a esa petición vieja.
  El flag funciona así:

  Al cleanup del efecto `return () => { cancelled = true }`, marcas que esa "versión" del efecto ya no es válida.
  En el .then, solo llamas setReports si !cancelled: es decir, si el efecto no se limpió todavía.
  En resumen: no actualizas el estado si la petición llegó tarde o el efecto ya se canceló.

  Nota: esto no aborta la petición HTTP (sigue en red); solo ignora el resultado. Para cancelar de verdad usarías AbortController en el fetch/axios.
</Aside>

```diff lang="tsx" title="src/hooks/useReports.ts" "<Report[]>"
  import { useEffect, useState } from 'react';
  import { getReports } from '../api/jasper-report-api';
+ import type { Report } from '../types/jasper-reports.types';

  export const useReports = () => {
+    const [reports, setReports]  = useState<Report[]>([]);
+    const [loading, setLoading]  = useState(false);
+    const [error, setError]      = useState<string | null>(null);

+    useEffect(() => {
     let cancelled = false;
+    setLoading(true);

+     getReports()
+        .then((data) => {
+          !cancelled && setReports(data);
+        })
+        .catch((e) => {
+          !cancelled && setError(e.message);
+        })
+        .finally(() => {
+          !cancelled && setLoading(false);
+        });

      return () => {
        cancelled = true;
      };
    }, []);

    return {
      reports,
      loadingReports,
      errorLoadingReports
    };
  };
```

## Aplicación en el proyecto

- El **módulo API** concentra URLs y cabeceras de JasperReports; si cambia la versión de `rest_v2`, tocas **un sitio**.
- El **hook** aísla el ciclo de vida React: montaje → petición → `setReports`. Los componentes solo llaman a `useReports()` y renderizan; no conocen la ruta `/resources`.
- Más adelante puedes **reutilizar** las mismas funciones de `jasper-report-api.ts` (`getReportExecution`, `getReportInputControls`, …) desde otros hooks o efectos sin duplicar Axios.

## Resumen rápido

| Pieza | Responsabilidad |
| :---- | :-------------- |
| `getReports` | `GET` recursivo de `reportUnit` → `resourceLookup` |
| `useReports` | Estado `reports`, carga en montaje, objeto de retorno para la UI |

## Convención práctica

<Steps>
1. Mantén **funciones HTTP** en `api/` y **estado** en `hooks/` (o en slices si más adelante usas un store).
2. **No** dejes promesas sin `.catch` en producción: al menos registra el error y opcionalmente muestra feedback en UI.
3. Si añades filtros o refresco manual, pasa de `[]` a dependencias bien definidas (`[deps]`) o extrae la carga a una función `reload()` para no disparar peticiones en bucle.
</Steps>
